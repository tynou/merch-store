# Магазин мерча

[Реализация тестового задания для стажёра Backend-направления в Авито.](https://github.com/avito-tech/tech-internship/blob/main/Tech%20Internships/Backend/Backend-trainee-assignment-winter-2025/Backend-trainee-assignment-winter-2025.md)

Backend-сервис для внутреннего магазина мерча.

## Описание проекта

Сервис позволяет сотрудникам:
- Покупать мерч за внутреннюю валюту
- Переводить монеты другим сотрудникам
- Просматривать историю операций с монетами
- Просматривать купленные товары

Каждый новый сотрудник получает 1000 монет при регистрации.

## Технологический стек

- **Go** 1.26.3
- **PostgreSQL** 18
- **JWT** для аутентификации
- **Docker Compose** для развертывания
- **sqlc** для генерации кода работы с БД
- **golang-migrate** для миграций

## Требования

- Docker и Docker Compose
- Go 1.26+ (для локальной разработки)

## Запуск

### Через Docker Compose (рекомендуемый способ)

```bash
docker compose up --build
```

Сервис будет доступен по адресу: `http://localhost:8080`

### Локальный запуск

1. Создайте файл `.env` на основе `.env.example` и заполните переменные.

2. Запустите PostgreSQL (например, через Docker):
```bash
docker compose up db
```

3. Запустите сервис:
```bash
go run cmd/main.go
```

## API Endpoints

### Аутентификация
```
POST /api/auth
```
Тело запроса:
```json
{
  "username": "user",
  "password": "password"
}
```
При первой авторизации пользователь создается автоматически.

### Просмотр информации
```
GET /api/info
```
Headers: `Authorization: Bearer <token>`

Возвращает баланс, инвентарь и историю переводов.

### Покупка мерча
```
GET /api/buy/{item}
```
Headers: `Authorization: Bearer <token>`

Доступные товары: t-shirt, cup, book, pen, powerbank, hoody, umbrella, socks, wallet, pink-hoody

### Перевод монет
```
POST /api/sendCoin
```
Headers: `Authorization: Bearer <token>`

Тело запроса:
```json
{
  "toUser": "recipient",
  "amount": 100
}
```

## Принятые решения

### Транзакции и конкурентность
Для операций покупки и перевода монет используются транзакции с блокировкой строк. Это гарантирует консистентность данных при конкурентных запросах.

При переводе монет блокировка пользователей выполняется в порядке возрастания ID, чтобы избежать дедлоков.

### Аутентификация
JWT токены выдаются при авторизации. Токен содержит `user_id` и expires через 72 часа. При первой авторизации пользователь автоматически создается.

### База данных
Используется PostgreSQL с таблицами:
- `users` - пользователи и балансы
- `merch` - каталог товаров
- `purchases` - покупки
- `coin_transfers` - переводы монет

### Тестирование
- Юнит-тесты покрывают бизнес-логику (сервисы)
- E2E-тесты проверяют основные сценарии:
  - Покупка мерча
  - Перевод монет
- Используются моки (mockery) и testcontainers
